# 행사 준비 원큐! · V0.3

대학교 직원이 장소와 행사 종류에 맞춰 준비를 점검하는 정적 프로토타입입니다.

- 공개 사이트: https://erakeun.github.io/erica-event-oneq/
- 저장소: https://github.com/erakeun/erica-event-oneq
- GitHub Pages: `main` / 저장소 루트, 별도 빌드 없음

## V0.3: 준비에서 현장 운영까지

기존 7단계와 모든 제작기·샘플을 유지합니다. 마지막 단계 안에서 **준비표 / 현장점검 / 역할표 / 사후정리**를 전환합니다.

- 외부 참석 여부와 필요한 안내만 선택. 입력한 행사명·일시·정확한 장소·확인된 안내로 메시지를 복사합니다. 미입력 정보는 제외하며 자동 발송하지 않습니다.
- 다과·식사 필요 여부, 인원, 수령 시간, 배치 장소 및 식이 제한의 별도 확인 필요 여부를 준비표와 현장점검에 반영합니다. 개인별 건강정보는 저장하지 않습니다.
- 식순 단계의 접힌 역할분담에서 이름 또는 팀을 선택 입력합니다. 입력한 역할만 모바일·인쇄 역할표에 표시합니다. 역할표에서도 수정 가능합니다.
- 준비표는 사전 준비, 현장점검은 실물·배치·실제 작동을 별도로 관리합니다. 큰 체크 영역, 완료/남은 개수, 미완료 필터, 인쇄를 제공합니다.
- 행사 종료 후 촬영자료·활용·반납·보관·후속 행정과 다음 행사 메모를 제공합니다.
- 담당자 동선 보완: 준비표의 미완료 중 먼저 협의할 3개 항목을 우선 표시하고 해당 항목으로 이동. 현장점검에서 현재 선택한 식순을 접어 보기. 실제 MOU·식순 양식은 추후 제공 시 교체하며 기존 샘플은 유지.
- 추가 보완: 미정 항목에서 해당 입력으로 이동, 선택 변경 시 관련 현장 확인만 초기화, 저장 실패 경고, 담당자 공유용 현장 요약 복사.

`data.js`의 `GUEST_NEEDS`, `FOOD_OPTIONS`, `ROLE_TEMPLATES`, `GUEST_PREP`, `FOOD_PREP`, `ONSITE_ITEMS`, `AFTER_ITEMS`에서 설정을 관리합니다. `when`은 `operations.js`의 조건이며 `depends`가 바뀌면 해당 완료 상태를 재확인합니다. 렌더링은 `operations-view.js`, 기존 준비 흐름은 `app.js`에 있습니다.

기존 localStorage 키를 유지하며 스키마는 3입니다. V0.1/V0.2 입력·식순과 호환되는 준비 상태는 유지하고 현장점검은 새로 시작합니다. 직접 입력한 장소명이 바뀌면 확보 여부를 다시 묻고, 장소 변경 시 이전 상세 위치와 주차 안내를 지웁니다. 이름·메모는 해당 브라우저에만 저장하며 다른 기기에 자동 동기화하지 않습니다.

**V0.3 검증:** 자동 테스트 39개 통과. 수정 전 93개 화면, 수정 후 A~D와 168개 화면(1440/390/412px)을 실제 Chrome에서 검사했습니다. 12개 샘플 다운로드, 10개 외부 주소 응답, 저장 실패·이전 버전 복원·초기화 범위·클립보드/대체 복사·키보드·200% 글자 확대를 확인했습니다. 4가지 인쇄 화면의 PDF를 생성·렌더링하여 확인했습니다. 실제 프린터 출력 및 iOS Safari는 미검증입니다. 상세 내용은 `tests/VALIDATION-V0.3.md`를 참고하세요.

## 이전 V0.2 기능과 기록

- 서울캠퍼스 신본관 2층 회의실1 추가: 기존 전용 제작기 연결, 메인 49석 + 배석 4석 = 53석.
- 좌석 배치·명패·보도자료 필요 여부를 각각 선택. 선택한 장소의 전용 도구만 연결하며 다른 장소는 현장 배치를 직접 확인하도록 안내.
- 식순 5종·사회자 시나리오 5종·협약서 구성·환영사 작성 예시, 총 12개 TXT 다운로드.
- 촬영·취재 협조와 보도자료 업무 분리. 부총장 이상 참석 시 촬영 요청 안내를 먼저 강조.
- 필요한 결과물만 제작기 연결과 최종 준비표에 반영. 파일 제작과 현장 확인, 요청과 지원 확정은 별도 상태.
- 브라우저 뒤로/앞으로 이동, 다음 단계 이름 표시, 준비표 그룹별 선택 수정, 인쇄 시 선택 식순 포함.

식순과 문구는 검토 전 일반적인 준비 예시이며 공식 학교 지침이 아닙니다. 실제 예약·접수·발송·지원 확정은 수행하지 않으며 외부 링크를 열어도 준비표를 자동 완료 처리하지 않습니다. 운영 개인정보·기부금액을 수집하지 않습니다. 연결된 MACH/제작기 저장소는 변경하지 않았습니다.

## 실행과 테스트

```sh
python3 -m http.server 4173 --bind 127.0.0.1
# http://127.0.0.1:4173/
npm test
```

Node가 있으면 `npm start`로도 서버를 시작할 수 있습니다. 서비스 실행에 의존성 설치와 빌드는 필요하지 않습니다. `file://` 대신 HTTP 서버로 실행하세요.

브라우저 회귀 스크립트는 선택 개발 도구인 Playwright와 Chrome이 필요합니다. 서버를 켠 뒤 아래처럼 실행합니다. 브라우저 검증은 가상 데이터만 사용하고 `tests/browser-evidence/`에 결과를 남깁니다.

```sh
npm install --no-save --package-lock=false playwright
node tests/browser-v0.3.mjs
node tests/browser-edge-v0.3.mjs
```

## 설정과 파일

| 위치                            | 관리 내용                                                       |
| ------------------------------- | --------------------------------------------------------------- |
| `data.js` → `VENUES`            | 장소명·설명·대관 정보·`seatTool` 연결(링크 키, 버튼 문구, 안내) |
| `data.js` → `EVENTS[].agenda`   | 식순 제목·역할·현장 준비·사회자 멘트                            |
| `data.js` → `LINKS` / `OUTPUTS` | 기존 도구 URL·결과물 용도·현장 확인                             |
| `data.js` → `TEMPLATES`         | 자료 ID·`events`·`label`·`path`·`format`·`status`               |
| `app.js`                        | 조건부 화면·체크 상태·저장 복원·자료 응답 확인                  |
| `styles.css`                    | 반응형·키보드 포커스·인쇄 스타일                                |
| `tests/VALIDATION-V0.2.md`      | UX 감사·검증 결과·한계                                          |

`VENUES[].seatTool`이 없는 장소는 전용 도면을 연결하지 않습니다. 대관 담당·연락처·예약·이용 조건은 확인된 자료가 없어 `null`로 유지했습니다. ERICA 컨퍼런스홀 중강당은 장소 선택에 추가하지 않았습니다. LED 제작기는 접힌 참고 영역에 두며 선택 장소와의 호환 여부가 미확인임을 표시합니다.

## 샘플을 실제 파일로 교체하기

모든 TXT에 **V0.2 프로토타입용 임시 샘플**, **실제 양식으로 추후 교체 예정**을 명시했습니다. 학교 공식 문서나 최종 원고가 아닙니다. 협약서는 항목 구조만 제공하며 서명할 수 있는 계약서가 아닙니다.

1. 검토된 실제 파일을 `assets/templates/`에 넣습니다.
2. `TEMPLATES`의 `path`, `format` (`txt`, `hwp`, `docx`), `status` (`real`)를 변경합니다.
3. HTTP 서버에서 실제 다운로드와 원본 프로그램 열기를 확인합니다.

```js
// 실제 파일을 먼저 넣으세요. 아래 파일은 설명용이며 현재 존재하지 않습니다.
{
  id: 'agreement-mou', events: ['mou'], agendaIds: ['sign', 'exchange'],
  label: '협약서 예시', path: 'assets/templates/approved-agreement.hwp',
  format: 'hwp', status: 'real'
}
```

`agendaIds`는 관련 식순이 하나라도 포함된 경우만 노출하는 선택 필터입니다. 경로 이탈·미등록·404·HTML 대체 응답·연결 실패는 다운로드를 비활성화합니다. TXT는 UTF-8와 샘플 표시, HWP는 최소 크기/OLE 헤더, DOCX는 ZIP 헤더를 확인합니다. 이는 문서 내용이나 완전한 파일 호환성 검증이 아닙니다. 실제 문서는 등록자가 원본 앱에서 확인해야 합니다.

다운로드는 기본 예시입니다. 사용자가 화면에서 바꾼 식순과 준비 상태는 마지막 준비표와 인쇄에 반영됩니다.

## 저장·복원

V0.1 저장키 `erica-event-oneq:prototype:v0.1`를 유지하고 스키마 버전은 3입니다. V0.1/V0.2 데이터를 정규화해 이어받습니다. 이전 행사 정보·식순·관련 체크를 이어받습니다. 새로 추가된 좌석/홍보 결정은 ‘미정’으로 시작하며, 근거 없는 이전 완료 상태는 계승하지 않습니다. 저장 실패·손상된 데이터는 안전하게 안내합니다.

초기화는 확인 후 원큐 키만 지웁니다. 다른 앱의 저장 내용은 지우지 않습니다. 장소·일정·식순 등 관련 선택이 달라지면 해당 체크를 다시 할 일로 바꾸고, 필요 없어져 숨긴 항목은 상태에서도 제거합니다. 다른 기기·브라우저·주소와 자동 공유되지 않습니다.

## 확인 결과와 남은 자료

실제 HWP, 확인된 대관 창구·절차, 화면 제작기와 설치 장비의 대응 정보는 추후 등록해야 합니다. V0.3 인쇄 PDF의 페이지 나눔은 확인했으며, 실물 프린터 출력은 미검증입니다. 연결된 외부 시스템의 실제 예약·접수·제출은 하지 않았습니다.
