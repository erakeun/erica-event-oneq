# 행사 준비 원큐! · V0.1

대학교 직원이 장소와 행사 종류를 선택하며 준비를 점검하는 독립 정적 시제품입니다. PROJECT MACH 운영 홈페이지는 수정하지 않았습니다.

## 바로 시험하기

공개 사이트: **https://erakeun.github.io/erica-event-oneq/**

설치 없이 위 주소를 열어 사용할 수 있습니다.

로컬 개발 미리보기: **http://127.0.0.1:4173/**

로컬 주소는 서버가 실행 중인 컴퓨터에서만 접근됩니다. 공개 URL이 아니며, 서버가 종료되면 다음 명령으로 다시 실행하세요.

```sh
cd erica-event-oneq
python3 -m http.server 4173 --bind 127.0.0.1
```

그다음 Codex 내장 브라우저에서 위 주소를 여세요. Node가 있으면 같은 폴더에서 `npm start`도 가능합니다. 설치·빌드 과정은 필요 없습니다. ES 모듈과 파일 검증을 사용하므로 HTML을 더블클릭하는 `file://` 실행 대신 HTTP 서버를 사용하세요.

먼저 **프라임 컨퍼런스홀 → 협약식(MOU) → 부총장 이상 참석**을 선택해 보세요. 안내 단계를 이동한 뒤 준비표에서 직접 체크하고, 장소·유형을 바꿔 관련 체크가 다시 할 일로 돌아가는지 확인할 수 있습니다. 기본정보 없이 미정 상태로 끝까지 이동해도 됩니다.

## 구현한 범위

- 장소 → 행사 정보 → 먼저 요청할 일 → 식순·양식 → 좌석·명패 → 화면·안내물 → 준비표, 7단계와 직접 이동
- 지정된 장소 5개 및 확보 상태, 행사 종류 5개, 최소 기본정보와 양의 정수 인원 검증
- 모든 행사에 보도자료 안내, 참석 조건에 따른 촬영 안내 및 요청/지원 확정 분리
- 행사별 실질적인 식순·역할·준비물·진행 멘트 예시, 포함/제외·순서 이동·확인 후 복원
- 프라임에만 전용 좌석배치 연결, 장소와 무관한 명패 필요 여부 선택
- 필요한 화면·안내물 선택, 제작과 현장 확인을 구분한 준비표
- 수동 상태 3종, 관련 선택값에 따른 체크 무효화, 저장/복원/확인 후 초기화, 인쇄 스타일

실제 예약·신청·발송·제작, 운영 데이터 변경, 명단 수집, 로그인, AI API, 서버/DB, 통계 수집, 파일 업로드는 구현하지 않았습니다. 외부 도구는 새 탭 링크이며 사용자 입력을 URL에 추가하지 않습니다.

## 파일과 수정 위치

| 파일/설정 | 수정할 내용 |
| --- | --- |
| `index.html` | 서비스 이름, 헤더와 기본 문서 구조 |
| `styles.css` | 데스크톱·모바일·인쇄 스타일 |
| `app.js` | 단계 화면, 조건 분기, 체크 생성·무효화, 저장, 파일 검증 |
| `data.js` → `VENUES` | 장소명과 `rental.department`, `contact`, `url`, `conditions` |
| `data.js` → `EVENTS[].agenda` | 각 순서의 `title`, `what`, `role`, `check`, `script` |
| `data.js` → `LINKS` | 기존 제작기·협조 요청 주소 |
| `data.js` → `OUTPUTS` | 결과물 용도와 현장 확인 문구 |
| `data.js` → `TEMPLATES` | 자료의 `id`, `event`, `label`, `path` |
| `assets/templates/` | 추후 제공받는 실제 HWP 파일 |
| `tests/core.test.mjs` | 분기·상태·저장·입력·파일 경로 자동 테스트 |
| `tests/VALIDATION.md` | 실제 수행한 검증과 남은 한계 |
| `tests/REFERENCES.md` | 기존 사이트 읽기 전용 대조 결과 |
| `tests/screenshots/` | 실제 구현 화면 3장 |

장소의 담당 부서·연락처·예약 URL·이용 조건은 **사용자가 확인한 정보만** 등록하세요. 현재는 `null`이며 프라임·히스토리·기타 장소에 ‘대관 안내 정보 확인 필요’를 보여 줍니다. 부서 자체 장소에는 외부 대관 안내를 표시하지 않습니다.

### 실제 HWP를 등록하는 방법

1. 제공받은 실제 `.hwp`를 `assets/templates/`에 넣습니다.
2. `TEMPLATES`에서 해당 자료의 `path`를 상대경로로 바꿉니다.
3. HTTP 서버로 식순·양식 단계를 열어 다운로드 활성화와 파일 내용을 직접 확인합니다.

다음은 **설명용 등록 예시이며 이 파일은 현재 존재하지 않습니다.**

```js
// 실제 파일을 먼저 넣은 뒤에만 등록하세요.
{ id: 'agreement-mou', event: 'mou', label: '협약서 예시',
  path: 'assets/templates/사용자가-제공한-협약서-예시.hwp' }
```

브라우저는 허용된 폴더·`.hwp` 확장자·경로 이탈 여부를 확인하고, 실제 GET 응답과 최소 크기 및 OLE 파일 헤더를 확인합니다. 없거나 잘못된 파일, HTML 대체 응답, 연결 실패는 다운로드를 활성화하지 않습니다. 이 검사는 HWP 본문이나 법적 유효성 검증이 아니며, 실제 HWP 호환성과 내용은 자료 등록 시 확인해야 합니다. 원본이 없는 현재는 모든 `path`가 `null`입니다. 테스트용 임시 파일은 OS 임시 폴더에 만들고 테스트 종료 시 삭제합니다.

## 저장과 상태 변경

저장키는 `erica-event-oneq:prototype:v0.1` 하나입니다. 이 브라우저·접속 주소에만 저장되며 다른 기기와 공유되지 않습니다. `localhost`와 `127.0.0.1` 또는 포트가 다르면 별도의 브라우저 저장소입니다.

‘처음부터 다시’는 확인 후 이 앱의 키만 삭제합니다. `localStorage.clear()`는 사용하지 않습니다. 저장 차단·용량 제한·손상된 JSON은 예외를 처리해 안내를 계속 보여 줍니다. 저장 실패 시 성공 문구를 표시하지 않습니다.

준비표는 안정적인 항목 ID와 관련 선택의 서명을 함께 사용합니다. 장소 변경 시 확보 상태와 관련 체크, 행사 종류/식순 변경 시 진행·준비물 체크, 참석 조건 변경 시 촬영 체크를 재확인하게 합니다. 날짜 변경 시에도 장소와 촬영 요청·확정을 재확인합니다. 숨겨진 항목은 체크 상태에서도 제거되며, 무관한 기본정보·체크는 보존합니다. 외부 링크, 다운로드, 다음 단계는 완료 처리하지 않습니다.

## 검증

확인 환경: macOS, Node.js v22.23.2, Python 3.9.6, Codex 내장 브라우저. 앱 런타임 의존성 없음.

```sh
npm test
# 또는
node --test tests/core.test.mjs
```

자동 테스트 **20개 통과**. 그중 조합 검사에서 장소×행사×참석×명패 **225개 조합**을 확인했습니다. A~G는 내장 브라우저로도 실제 조작했습니다. 기본 미정 상태와 대표 협약식 각각 7단계를 1440/390/412px에서 검사해 **42개 단계·폭 조합에서 가로 넘침과 잘린 버튼 없음**을 확인했습니다. `/erica-event-oneq/` 하위 경로에서 모듈 로드·단계 이동·새로고침도 확인했습니다.

HWP 미등록, 존재하지 않는 경로, 위험한 경로, HTML 응답, 연결 실패와 실제 임시 경로의 가상 파일을 검증했습니다. 실제 사용자 HWP는 미제공으로 다운로드·한글 프로그램 열기까지는 미검증입니다.

인쇄 버튼과 전용 `@media print` 스타일은 구현했습니다. 내장 브라우저에서 버튼을 실행했으나 접근 가능한 인쇄 미리보기/OS 대화상자가 제공되지 않아 **실제 페이지 나눔·프린터 출력은 미검증**입니다. 선택 항목의 상태를 텍스트로 출력하고 메뉴·버튼·선택 컨트롤을 숨기며 행 내부 페이지 분할을 피하도록 설정했습니다.

기존 주소는 읽기 전용 GET 및 코드 대조만 했습니다. 실제 접수·제작·지원 확정·현장 송출은 수행하거나 검증하지 않았습니다.

## 추가로 필요한 자료

- 행사 종류 5종의 실제 식순지 HWP
- 협약식용 협약서 예시 HWP
- 장소별 확인된 담당 부서, 연락처, 예약 URL, 이용 조건
- 각 화면 제작기와 실제 설치 장소·장비의 대응 정보

기한·비용·수용 인원·장비·대관 절차는 확인되지 않아 임의로 넣지 않았습니다. LED 제작기는 프라임용으로 추천하지 않습니다. 식순과 진행 멘트는 검토 전 예시이며 학교의 공식 의전 지침이나 실제 과거 행사가 아닙니다.

## Git·배포 상태

GitHub 저장소: https://github.com/erakeun/erica-event-oneq

원큐는 기존 MACH 저장소와 분리된 전용 저장소입니다. 시제품을 로컬에서 개발·검증한 뒤, 사용자의 GitHub 업로드·병합 요청에 따라 [PR #1](https://github.com/erakeun/erica-event-oneq/pull/1)을 통해 GitHub `main`에 병합했습니다. 구현 병합 커밋은 `9f2ab57`입니다. 이전 로컬 병합 기록은 개발 작업 폴더에 보존했습니다.

사용자의 저장소 공개 전환 승인에 따라 저장소를 Public으로 전환하고 GitHub Pages 공개 배포를 완료했습니다. 배포 소스는 `main`의 `/ (root)`이며 HTTPS를 사용합니다. 기존 MACH 바로가기와 운영 도구는 변경하지 않았습니다. GitHub 저장소에서는 소스 코드와 검증 기록을 확인할 수 있으며, 로컬에서도 위의 실행 방법으로 사용할 수 있습니다.

GitHub Pages로 추후 배포할 때는 정적 파일을 저장소 루트에 그대로 둘 수 있습니다. 경로는 상대경로이며 서버 라우팅이 필요한 URL을 사용하지 않습니다. 이번 버전에는 배포 워크플로를 추가하지 않았습니다.

공개 배포 후 확인: 2026-09-21. 로그인 없는 HTTP 요청으로 `index.html`, `styles.css`, `app.js`, `data.js`의 200 응답과 로컬 원본 일치를 확인했습니다. Codex 내장 브라우저에서 프라임·협약식·부총장 이상 참석 → 촬영 안내 → 준비표 → 새로고침을 확인했으며 오류 로그는 없었습니다. 최초 Pages 빌드/배포는 [성공 기록](https://github.com/erakeun/erica-event-oneq/actions/runs/35565918180)에서 볼 수 있습니다.
